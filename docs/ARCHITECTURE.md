# 架构与状态机

## 服务边界

- 管理服务 `9527`：Web UI、REST API、企业微信回调。
- 播放网关 `9096`：Jellyfin 反向代理和 `/direct/{mediaID}`。
- SQLite：加密配置、任务、媒体台账、消息去重和审计记录。
- 115 Provider：所有非公开 115 协议集中在单一适配层。

## 转存状态

```text
queued
  -> transferring
  -> received
  -> matching
  -> waiting_match | organizing
  -> verifying
  -> completed
```

任意执行阶段可进入 `failed`。转存任务从已持久化的接收目录继续；分类复制持久化尝试和目标目录 ID，结果不确定时不自动重复复制。本地整理通过远端文件 ID 和已保存的选择保持幂等。

## 到账确认

任务先创建以分享名称和任务 ID 标记的接收目录，再将 `/share/snap` 的顶层文件 ID 提交给 `/share/receive`。接口接受后轮询独立接收目录；实际条目数量达到预期才进入 `received`。收到的内容保留原样，不再执行历史接收目录重命名或七天自动清理。

## 匹配与整理

显式 `tmdb:movie:ID` 或 `tmdb:tv:ID` 直接查询详情。自动匹配使用标题 55、年份 25、媒体类型 15、名称一致性 5 的百分制；第一名至少 85 且领先第二名至少 10 才自动执行。

115 归档仅按 `电影/华语电影|日韩电影|欧美电影`、`电视剧/国产剧|日韩剧|欧美剧|纪录片|日番|国漫` 分类复制整个原始目录，不逐文件重命名，不上传 NFO、海报或背景图。接收原件保留。

本地按 TMDB 标题、年份和 ID 生成标准目录和 STRM 名称；电影、电视剧、季、剧集 NFO 以及海报和背景图仅写入本地。电视剧按季查询 TMDB，不为每集重复查询整季。图片下载失败记录日志，核心元数据失败则任务可重试。已有同步目录的本地整理不调用 115。单个工作队列和共享媒体库锁串行处理整理、刮削与同步，避免台账和文件路径互相覆盖。

## 同步与删除

同步器按配置周期执行增量扫描，只添加或更新媒体；每 24 小时执行一次完整校准。完整校准递归扫描整理目录，通过远端文件 ID 维护台账，第一次缺失只将 `missing_count` 加一，连续第二次完整校准仍缺失才删除本地 STRM。增量扫描不会增加缺失计数，远端 115 文件永远不会被同步器删除。

没有 TMDB 标记的新文件先同步到本地 `待整理`；同步有变化时将本地匹配、整理、刮削任务排队。`local_organization` 保存远端 ID 对应的本地相对路径，后续远端改名或扫描不会覆盖本地整理结果，媒体签名 ID 保持不变。

## 播放

PlaybackInfo 中识别到本项目签名 URL 的媒体源采用严格原片直链模式：标记为可 DirectPlay/DirectStream，设置 `SupportsTranscoding=false`，移除转码地址、容器和协议字段。这里的 DirectStream 是原文件 302，不是服务器重新封装。网关拦截这些媒体的 HLS/DASH 播放列表和分片请求，返回 `409 direct_play_required`，不转发给 Jellyfin，也不请求 115。原片流和下载请求则返回 302；普通本地媒体保持 Jellyfin 原有行为。媒体源查询失败直接报错，不回退到服务器播放代理。

`/direct` 对客户端校验 HMAC 和当前 Jellyfin 用户的 `EnableMediaPlayback`；Jellyfin 服务端元数据探测使用独立 HMAC，并同时校验请求来源为已配置的 Jellyfin 主机。元数据探测保留，不属于播放转码。网关以实际请求 UA 向 115 换取短时 CDN URL，缓存键为 `pickcode + UA`，有效期不超过 25 分钟或 CDN URL 自身到期时间。客户端负责原片解码；格式不兼容时播放失败，不启动服务器转码兜底。日志只记录媒体 ID、投递模式和 CDN 主机名，不记录完整签名链接或用户令牌。
