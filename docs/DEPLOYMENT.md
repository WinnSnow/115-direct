# 部署检查表

## 网络

- 管理域名反代 `127.0.0.1:9527`。
- 媒体域名反代 `127.0.0.1:9096`，关闭代理缓冲并支持 WebSocket。
- 企业微信可从公网访问 `https://管理域名/callbacks/wecom`。
- Jellyfin 客户端只使用媒体域名，不绕过网关访问后端 Jellyfin。

## 存储

- 持久化整个 `DATA_DIR`，尤其是数据库和 `master.key`。
- 将宿主机 `/media/115-strm` 挂载到本服务的同一路径，并保证容器 UID 1000 可写。
- 单独挂载 `/media/115-pending`，配置`PENDING_HOST_PATH`；与成品根独立，不互相包含，不加入Jellyfin扫描。
- 将 `/media/115-strm` 以只读方式挂载到 Jellyfin，例如 `/media/115-direct:ro`。
- 硬链接要求两个目录位于同一文件系统、同一个容器挂载内。分别绑定两个目录即使设备号相同也会报 `EXDEV`。使用 Docker Compose 2.24.4 或更新版本执行 `docker compose -f docker-compose.yml -f docker-compose.hardlink.yml up -d`，设置 `MEDIA_HOST_PATH` 为仅存放待整理和成品目录的共同父目录；容器内仍使用 `/media/115-pending` 和 `/media/115-strm`。父目录若还有其他应用的数据，应为这些子目录额外添加只读挂载。Jellyfin 继续仅挂载成品目录。
- 备份必须同时包含数据库和主密钥，缺少主密钥时加密配置不可恢复。

## 企业微信

- 创建自建应用，记录 CorpID、AgentID 和 Secret。
- 回调模式使用管理台配置的 Token 与 EncodingAESKey。
- 系统设置 → 企业微信增加独立的“回调入口 Token”，点击随机生成并保存；“企业微信签名 Token”仍填写企业微信后台的 Token，两者独立。
- 填写“公网管理地址”（管理端域名），保存后点击“显示已保存回调地址”，将带 `access_token` 查询参数的完整地址复制到企业微信后台。入口 Token 验证在读取消息正文、校验签名和解密之前执行，缺少或错误时返回403；未配置入口 Token 时关闭回调处理。轮换并保存后旧地址立即失效，需更新企业微信后台。
- 入口 Token 加密保存，普通设置接口只返回掩码；完整地址仅在已登录管理员明确请求且通过CSRF校验后返回。回调反向代理访问日志使用 `$uri`（不含查询参数）而不是 `$request_uri`，避免记录完整入口密钥。
- 应用可见范围始终生效；管理台 UserID 留空时允许所有可见成员，填写后再叠加 UserID 白名单限制。
- 企业微信应用菜单可在系统设置中分别开启“网盘整理”“全量同步”“增量同步”；保存后点击“同步应用菜单”才会调用企业微信菜单接口。按钮事件仍受 UserID 白名单限制，网盘整理会校准115分类目录并移动可识别目录，同步调用现有全量或增量同步队列，重复点击由运行状态保护。关闭菜单后点击同步会删除应用菜单。
- “消息识别与分享更新”提供自动识别115分享开关、重复分享策略和检查间隔（默认10分钟，0表示每次检查）。支持链接内 `password/receive_code/pwd` 参数和消息内“提取码/密码”，每条消息发送一个分享。默认只在再次收到消息时核对分享目录，不启动网盘轮询。
- 同链接内容未变回复“已转存，无需重复发送”；文件夹内新增剧集或视频大小/SHA1变化会创建补充任务，只接收新增或变更文件，并保持源目录层级、历史任务及原有播放ID。删除分享中的文件不会自动删除已有文件。可发送 `检查更新 https://115.com/s/分享码?password=提取码` 跳过检查间隔或“直接提示已转存”策略；进行中、待识别或失败的任务需先完成或重试，不创建重复任务。
- 新任务保存提交时完整文件清单与内容指纹；旧任务首次核对会读取保留的接收原件建立历史基准。旧接收原件已清理且没有历史清单时提示人工核对，不以当前分享内容冒充历史版本。核对失败不会提示已转存，也不会创建新任务。
- 分批接收前记录持久步骤，结果不确定时重试只核对对应文件，不重复调用转存。完成后沿用分类、版本、本地整理和Jellyfin更新流程，并通知提交成员。

## Jellyfin

- 创建独立 API Key供刷新媒体库和连接测试使用。
- 电影库可扫描成品目录下的“电影”一级目录。电视剧库应将各二级分类目录分别加入同一个库，例如“电视剧/国漫”“电视剧/国产剧”；不要直接扫描“电视剧”一级目录，Jellyfin 会把二级分类误当成剧集。新增分类后补充其扫描路径。仅扫描成品目录，不扫描待整理目录。
- 手机、电视和桌面客户端的服务器地址改为媒体网关域名。
- 115 媒体只支持原片直链播放，不提供 HLS/DASH、服务器转码或重新封装兜底。客户端必须支持源文件的容器、视频及音频编码；浏览器不兼容时使用支持源格式的播放器。
- 更新网关后停止旧播放并重新开始，避免客户端继续使用缓存的转码地址。Jellyfin 元数据探测保留，普通本地媒体不受此限制。
- 系统设置“播放直链”的公网地址填写客户端使用的网关根地址；不要填写后端 Jellyfin 地址。CDN 播放前检查默认关闭，可针对单个 STRM 手动诊断。

## 上线验证

1. `/healthz` 返回 `ok`，`/readyz` 返回 `ready`。
2. 管理台显示 115 会话正常。
3. 测试分享任务依次到达“已落盘”和“已完成”。
4. Jellyfin 可看到新条目。
5. 播放响应为 `302`，Location 指向 115 CDN。
6. 手机向 CDN 发送 Range 并收到 `206`，服务端出口流量不包含视频内容。
7. 115 条目的 PlaybackInfo 返回 `SupportsTranscoding=false` 且没有 `TranscodingUrl`；旧 HLS/DASH 地址返回 `409 direct_play_required`，不产生新的播放转码进程。

第 5 步只证明网关取得直链并返回重定向；客户端实际直连需要第 6 步的网络请求或播放器日志确认。
